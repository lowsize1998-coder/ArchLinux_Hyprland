# Arch Linux · Rozetta · восстановление

Снимок конфигурации на **22 октября 2026 года**. Предназначен для возвращения
на Arch Linux с нынешним Hyprland rice после работы в Windows.

Сохранены Symphony со всеми установленными темами, Dreamcore и Zen, настройки
рабочего стола и приложений, пользовательские скрипты и службы, шрифтовые
настройки, значки, обои, инструкции PDF, пакетные списки с версиями и отдельные
настройки браузера и Obsidian.

Это позволяет воспроизвести конфигурацию. Тождественный образ ОС, старые версии
всех пакетов и совместимость текущего CSS с будущими версиями приложений этим
репозиторием не гарантируются. Версии и нестандартные сборки зафиксированы,
чтобы изменения можно было диагностировать.

## Сначала сохранить

Каталог репозитория и его архив сейчас находятся на Linux-диске. До удаления
Linux отправьте каталог в GitHub или скопируйте архив на другой носитель.
Личные файлы, Obsidian-заметки, проекты и сохранения игр храните отдельно:
они не являются конфигами и в этот публичный комплект не включены.

## Структура

```text
home/                  → восстановление в домашнюю папку нового пользователя
  symphony/            → реальные dotfiles, темы, обои и исходники оформления
  .config/             → ссылки, отдельные конфиги, службы и профили редакторов
  .local/              → launchers, значки, пользовательские инструменты
  .codex/              → модель, UI и темы; без авторизации и переписок
  Инструкции/          → отдельные PDF-памятки
profiles/
  zen/                 → CSS, хоткеи и выбранные настройки; без данных аккаунтов
  obsidian/.obsidian/  → оформление, горячие клавиши и код плагинов
  spotify/             → только безопасные параметры звука
inventory/             → пакеты, версии, службы, аппаратная конфигурация, проверки
system-reference/      → системные настройки для сравнения, без автоприменения
build/waybar/          → исходный архив и патчи пользовательского Waybar
scripts/               → восстановление с предварительным просмотром и backup
docs/                  → порядок установки, ограничения и настройка приложений
```

## Восстановление

На новой установленной Arch, обычным пользователем:

```sh
# 1. Установить git и python средствами Arch, затем клонировать свой репозиторий.
git clone https://github.com/YOUR-USER/YOUR-REPOSITORY.git ~/arch-restore
cd ~/arch-restore

# 2. Проверить содержимое и посмотреть план.
python3 scripts/restore.py --verify
python3 scripts/restore.py

# 3. Установить сохранённый набор официальных пакетов.
bash scripts/install-packages.sh --apply

# 4. Применить пользовательские конфиги с backup заменяемых файлов.
python3 scripts/restore.py --apply

# 5. Выполнить шаги приложений из docs/APPLICATIONS.md.
# 6. В новом сеансе Hyprland/UWSM включить пользовательские службы.
bash scripts/activate-desktop.sh --apply
```

`restore.py` без `--apply` ничего не записывает. Он не форматирует диски,
не меняет `/etc`, загрузчик и драйверы, не завершает приложения и не запускает
сохранённые сторонние установщики. Перед заменой файлов сохраняется backup
в `~/.local/state/arch-restore/backups/` с картой исходных путей.
Пути `/home/rozetta` в текстовых файлах заменяются на домашний каталог нового
пользователя; символические ссылки переназначаются на восстановленное дерево.

Полный порядок: [docs/RESTORE.md](docs/RESTORE.md).
Приложения: [docs/APPLICATIONS.md](docs/APPLICATIONS.md).
Исключённые данные: [docs/EXCLUDED.md](docs/EXCLUDED.md).

## Добавление в GitHub

Публикуйте **содержимое этого каталога**, а не весь `/home/rozetta` и не архив
резервной копии. В каталоге специально нет старой истории Git.

```sh
git init -b main
git add .
git commit -m "Save Arch Hyprland configuration 2026-10-22"
git remote add origin https://github.com/YOUR-USER/YOUR-REPOSITORY.git
git push -u origin main
```

Выполнить эти команды предстоит владельцу репозитория: текущая задача не
создаёт удалённый репозиторий и не выполняет push. Для сохранения ссылок
и Unix-режимов файлов удобнее сделать первый commit из Linux.

Среди файлов есть ресурсы больше 25 MiB, поэтому предпочтительна загрузка
через Git. Все файлы проверяются на лимит обычного GitHub-файла 100 MiB.
Архив комплекта предназначен для отдельного носителя или GitHub Releases,
а не для добавления одним большим файлом в обычный Git-репозиторий.
Основание: [ограничения GitHub](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github).
